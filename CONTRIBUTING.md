# Contributing to Mapping Workbench

Thanks for considering a contribution. This document covers the practical
steps: the licensing agreement you need to agree to, and how to submit changes.

## Contributor License Agreement

Before we can accept your contribution, you need to agree to the
[Contributor License Agreement](CLA.md) (CLA) — it explains what it grants
and what you keep. By opening a pull request, you agree to it; no separate
signature step is needed.

If you are contributing on behalf of your employer, see
[Section 7 of the CLA](CLA.md#7-contributing-on-behalf-of-an-entity) and
contact **hi@meaningfy.ws** first.

## Submitting changes

1. Open an issue first for anything beyond a small fix, so we can discuss
   the approach before you put in the work.
2. Fork the repository and create a branch for your change.
3. Keep pull requests focused — one change per PR is easier to review and
   merge.
4. Make sure existing tests pass and add tests for new behaviour where it
   makes sense.
5. Open the pull request against `develop` and describe what the change
   does and why.

## Code of conduct

Be respectful and constructive. Disagreements about code are fine;
disrespect towards contributors is not.

## Questions

For anything not covered here — licensing questions, contribution scope,
or anything else — reach out to **hi@meaningfy.ws**.
